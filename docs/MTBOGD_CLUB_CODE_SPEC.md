# MTBogd API — Клубын кодоор гишүүнчлэл тодорхойлох заавар

**Хэнд:** MTBogd API хөгжүүлэгч
**Хэнээс:** UB Golf (ubgolf.club)
**Огноо:** 2026-07
**Хамрах хүрээ:** External API v1 — `POST /external/v1/bookings`

---

## 1. Товч агуулга

UB Golf апп нь захиалга баталгаажуулахдаа хэрэглэгчийн **клубын кодыг**
(`customer.clubCode`) хамт илгээдэг боллоо. Одоогоор та нар гишүүн/сениор
тарифыг **утасны дугаараар** тааруулж байгаа. Үүнийг **клубын кодоор**
тодорхойлдог болгохыг хүсэж байна (утас нь нөөц хувилбар хэвээр үлдэнэ).

---

## 2. UB Golf-оос одоо илгээж буй payload

`POST /external/v1/bookings` (header: `x-api-key: mbg_live_...`)

```json
{
  "holdId": "hold_abc123",
  "customer": {
    "firstName": "Bat-Erdene",
    "phone": "99119007",
    "clubCode": "M-1234"        // ← ШИНЭ талбар (заавал биш)
  },
  "players": [
    { "name": "Bat-Erdene" },
    { "name": "Bat-Erdene" }
  ],
  "notes": ""
}
```

- `clubCode` нь хэрэглэгч профайлдаа MTBogd клубын кодоо оруулсан үед л явна.
- Код оруулаагүй хэрэглэгчийн хувьд `customer`-т `clubCode` талбар **байхгүй** —
  өмнөх шигээ зөвхөн `firstName` + `phone` явна.
- Кодын формат: хэрэглэгчийн оруулсан чөлөөт текст (та нарын өгсөн кодын
  формат ямар байх ёстойг хэлж өгвөл бид талбар дээр validation нэмж болно).

## 3. Хүсэж буй өөрчлөлт (MTBogd тал)

`POST /external/v1/bookings` боловсруулахдаа:

1. **`customer.clubCode` байвал** — гишүүнчлэлийн бүртгэлээс энэ кодоор хайж,
   олдвол тухайн гишүүний ангилалд (member / senior г.м.) тохирох тарифыг
   хэрэглэнэ. Утасны дугаарыг **үл харгалзана** (код нь эцсийн үнэн).
2. **Код олдохгүй / буруу бол** — одоогийн логик руу буцна: утасны дугаараар
   тааруулж үзээд, олдохгүй бол guest тариф.
3. **`clubCode` талбар байхгүй бол** — одоогийн логик өөрчлөгдөхгүй
   (утасаар таарвал member, үгүй бол guest).

Хүснэгтээр:

| clubCode | Утас таарсан | Хэрэглэх тариф |
|----------|--------------|----------------|
| Зөв код | — | Кодын гишүүний ангилал (member/senior) |
| Буруу/олдоогүй код | Тийм | Утасны гишүүний ангилал |
| Буруу/олдоогүй код | Үгүй | Guest |
| Байхгүй | Тийм | Утасны гишүүний ангилал (одоогийн байдал) |
| Байхгүй | Үгүй | Guest (одоогийн байдал) |

## 4. Хариу (response) — өөрчлөлт шаардлагагүй, гэхдээ хүсэлт

Одоо `GET /external/v1/bookings/{id}/qpay-status` нь `amount` +
`customerType` (`member`/`guest`) буцаадаг — UB Golf энэ утгыг хэрэглэгчид
"гишүүний үнэ / зочны үнэ" гэж харуулдаг.

**Хүсэлт:** боломжтой бол `customerType`-д `senior` г.м. ангиллыг ялгаж
буцаана уу — бид UI дээр ялгаж харуулна. (Заавал биш; `member`/`guest`
хэвээр байсан ч болно.)

Мөн боломжтой бол `POST /bookings`-ийн response-д тухайн захиалгад ямар
тариф оноогдсоныг (`customerType`, `ratePlan` г.м.) оруулж өгвөл бид
захиалга үүсмэгц зөв үнийг шууд харуулах боломжтой болно.

## 5. Юу өөрчлөгдөхгүй

- `POST /external/v1/booking-holds` — өөрчлөлтгүй.
- `GET /external/v1/tee-times` — өөрчлөлтгүй (үнэ нь урьдчилсан байдлаар
  guest тарифаар харагддаг нь хэвээр OK).
- Cancel / sync-players / QPay урсгалууд — өөрчлөлтгүй.
- `clubCode`-гүй хуучин клиентүүд яг өмнөх шигээ ажиллана
  (**backwards compatible**).

## 6. Тест хийх чеклист

1. `clubCode` = зөв гишүүний код, утас = бүртгэлгүй дугаар
   → **member тариф** (кодоор таарсан).
2. `clubCode` = зөв сениор гишүүний код → **senior тариф**.
3. `clubCode` = буруу код, утас = гишүүний дугаар → **member тариф**
   (утасны fallback).
4. `clubCode` = буруу код, утас = бүртгэлгүй → **guest тариф**.
5. `clubCode` байхгүй (хуучин payload) → одоогийн логик, регрессгүй.
6. `qpay-status` дээр `amount` нь оноогдсон тарифтай таарч байгаа эсэх.

## 7. Асуулт (бидэнд хариулж өгнө үү)

1. Клубын кодын **формат** ямар байх вэ? (жишээ: `M-1234`, тоо дан г.м.) —
   бид профайлын талбарт validation/жишээ нэмнэ.
2. Талбарын нэр `customer.clubCode` тохирох уу, эсвэл өөр нэр
   (`memberCode` г.м.) хүлээж авахаар хийх үү? — хэлбэл бид нэрийг тааруулна.
3. Нэг захиалгад **олон тоглогчийн** код дамжуулах шаардлага гарвал
   (`players[].clubCode`) дэмжих боломжтой юу? — одоогоор захиалга үүсгэгчийн
   код л явж байгаа.
